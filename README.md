# Library Management System

## Описание проекта

Library Management System — это система управления библиотекой, позволяющая пользователям заказывать книги и управлять библиотечными ресурсами. Проект реализован с использованием микросервисной архитектуры, что обеспечивает гибкость и масштабируемость.

## Архитектура

Система состоит из следующих микросервисов:

- **Book Service**: Управляет информацией о книгах.
- **Shared Service**: Сервис для выделения общих сущностей для других сервисов.
- **Book Order Service**: Обрабатывает заказы на книги.
- **Auth User Service**: Обеспечивает аутентификацию и авторизацию пользователей.
- **Discovery Service**: Реализует обнаружение сервисов.
- **API Gateway**: Упрощает взаимодействие между клиентами и микросервисами.
- **Identity Service**: Управляет данными пользователей.
- **PostgreSQL**: Основная база данных для хранения информации о пользователях и книгах.
- **Redis**: Используется как кэш для повышения производительности.

## Технологии

Проект использует следующие технологии:

- **Spring Boot**: Для разработки микросервисов.
- **Docker**: Для контейнеризации сервисов.
- **Feign**: Для синхронного взаимодействия между сервисами.
- **WebClient**: Для асинхронных HTTP-запросов.
- **gRPC**: Для высокопроизводительного удаленного вызова процедур.
- **Kafka**: Для обработки событий и обмена сообщениями.
- **Circuit Breaker**: Для повышения надежности взаимодействия между сервисами.

## Установка и запуск

Для запуска проекта выполните следующие шаги:

1. Убедитесь, что у вас установлены [Docker](https://www.docker.com/) и [Docker Compose](https://docs.docker.com/compose/).
2. Склонируйте репозиторий:
   ```
   git clone <repository-url>
   cd <project-directory>
3. Запустите контейнеры с помощью Docker Compose:
   ```
   docker-compose up -d

## Взаимодействие между сервисами

В проекте реализованы различные подходы к взаимодействию между сервисами:

- **Feign**: Упрощает HTTP-запросы к другим микросервисам.
- **WebClient**: Для асинхронного взаимодействия с внешними API.
- **gRPC**: Для высокопроизводительных взаимодействий.
- **Kafka**: Для обработки сообщений и событий.

## Паттерны проектирования

В проекте используются следующие паттерны:

- **Circuit Breaker**: предотвращает каскадные сбои, временно прекращая запросы к недоступным сервисам.
- **API Gateway**: служит единой точкой входа для клиентских запросов.
- **Discovery Service**: позволяет сервисам автоматически обнаруживать друг друга.

## Состав контейнеров

Контейнеры описаны в файле `docker-compose.yml`. Для их настройки и запуска следуйте инструкциям в разделе [Установка и запуск](#установка-и-запуск).
